# NeoToyBox Public Design v0.18

This is the public, synthetic example design. It is distinct from the private operations design.

## Scope

Provide an offline IPv4/MAC/VMID validator, synthetic prod/stg/dev examples, unit tests and selected Caddy/PHP/DB/cache/monitoring templates. Deployment orchestration and backup/restore execution are outside this package.

## Example environments

| Environment | Synthetic network family | VMID rule |
|---|---|---|
| prod | 10.80.*.0/24 | Base third/fourth octets |
| stg | 10.81.*.0/24 | Prefix 2 |
| dev | 10.82.*.0/24 | Prefix 3 |

Networks reserve .1 for the gateway and .10–.199 for reservations, with no dynamic pool. MACs are local-administered examples. Names resolve only under internal.example.invalid in documentation.

## Trust boundary

Public CI uses GitHub-hosted runners with contents: read. No self-hosted runner, deployment environment or infrastructure secret is attached. Changes go through a branch and PR. merge-gate requires successful execution of a nonempty test suite; skipped/failed/cancelled checks do not qualify.

A private operator may review and pin a public commit hash before adapting examples in private, validating dev/stg, completing site acceptance and explicitly approving production apply. Public code merge is not deployment approval.

## Data exclusion

Production IPAM, real FQDNs, NAS exports, personal metadata, secrets including SOPS files, keys/certificates, databases, backups, logs, plans and private Git history are excluded. Publication uses an exact file/hash allowlist and rejects unreviewed additions.

## Validation limits

Static checks and unit tests validate example code and syntax. They do not establish Nextcloud compatibility, live network security, backup restorability, WAN performance or production readiness. Human review remains necessary before publication.
