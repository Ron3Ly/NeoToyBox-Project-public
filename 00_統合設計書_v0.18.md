# NeoToyBox Public Design v0.18

This is the public, synthetic example design. It is distinct from the private operations design.

## Scope

Provide an offline IPv4/MAC/VMID validator, synthetic dev and prod examples, unit tests and selected Caddy/PHP/DB/cache/monitoring templates. Deployment orchestration and backup/restore execution are outside this package.

The production PVE host is intended to run Nextcloud and additional long-lived application projects. Each project should be independently deployable and use the same network and monitoring infrastructure.

## Example environments

| Environment | Synthetic network family | VMID rule |
|---|---|---|
| prod | 10.80.*.0/24 | Base third/fourth octets |
| dev | 10.82.*.0/24 | Prefix 3 |

Networks reserve .1 for the gateway and .10–.199 for reservations, with no dynamic pool. MACs are local-administered examples. Names resolve only under internal.example.invalid in documentation.

Dev runs on a dedicated validation machine, and prod runs on a separate PVE host. Set the PVE connection and guest sizes independently in each private inventory. The public guest allocations are examples. Both environments use Nextcloud's built-in preview providers. When adapting an existing installation, remove any custom Imaginary provider and endpoint from the private Nextcloud configuration and verify previews in dev before retiring its guest.

## Production guest budget

The example below assumes one or two concurrent Nextcloud users. It includes the shared monitoring guests and a private CI runner. Size OPNsense, future applications and the PVE host separately. Guest CPU counts describe shared virtual CPUs. The disk column covers guest disks and assumes separate storage for user files and backups.

| Guest | Type | vCPU | RAM (GiB) | Disk (GiB) |
|---|---|---:|---:|---:|
| Caddy | VM | 2 | 2 | 16 |
| Nextcloud | LXC | 4 | 8 | 16 |
| ONLYOFFICE Docs | VM | 4 | 6 | 64 |
| MariaDB | LXC | 2 | 8 | 16 |
| Valkey | LXC | 1 | 2 | 8 |
| Grafana, Loki and Prometheus | VM | 2 | 6 | 16 |
| Zabbix | VM | 2 | 4 | 16 |
| Private CI runner | VM | 2 | 2 | 16 |
| **Total** | **5 VMs, 3 LXCs** | **19** | **38** | **168** |

The MariaDB budget includes the 3 GiB InnoDB buffer pool. Valkey stores PHP sessions in memory, with automatic snapshots and the append-only log disabled. Its disk covers Debian, logs and updates. Before testing the full stack, adapt the dev fixtures to the validation machine, particularly the database memory limit and the document server's installation space.

## Proposed Ansible project boundaries

Start with separate project playbooks and inventory groups in the private Ansible repository. One shared inventory per environment keeps VMIDs, addresses and resource assignments unique. The following ownership model can also accommodate separate application repositories later.

| Owner | Managed resources | What changes when adding an application |
|---|---|---|
| Shared infrastructure | PVE bridges and IPAM, OPNsense, Caddy ingress, monitoring and log collection | Reserve the guest address and VMID, review routing and access, and register the hostname, health endpoint and monitoring targets. |
| Nextcloud | The Nextcloud guest, ONLYOFFICE, MariaDB and Valkey | Manage the application's own hosts, upgrades and data recovery. Consume the shared ingress and monitoring services. |
| Additional web project | Its own guest, application roles, data and deployment credentials | Supply its resource request, upstream address, health check and data protection requirements. Target its own inventory group. |
| Private CI | Runner and project-specific job credentials | Grant jobs the access needed for their project. |

The current Caddy and Prometheus templates reference the two existing public endpoints directly. Before onboarding another project, move the routes and probe targets into reviewed inventory variables. Keep firewall and shared monitoring changes in the infrastructure project. Test changes on dev and promote the same revision to prod. Retiring an application removes its registrations and guests while preserving the shared services.

Budget shared services once per environment. Before accepting a new guest, check actual guest-storage free space, host memory availability, peak CPU and disk I/O during jobs, and log growth. Keep a local boot path for a virtual router and a management path that works during a router restart. A single PVE host creates a common outage window for routing and applications.

## Trust boundary

Public CI uses GitHub-hosted runners with contents: read. No self-hosted runner, deployment environment or infrastructure secret is attached. Changes go through a branch and PR. merge-gate requires successful execution of a nonempty test suite; skipped/failed/cancelled checks do not qualify.

A private operator may review and pin a public commit hash, adapt the examples in private and complete site acceptance in dev. Production apply requires explicit approval of the revision tested in dev. Public code merge is not deployment approval.

## Data exclusion

Production IPAM, real FQDNs, NAS exports, personal metadata, secrets including SOPS files, keys/certificates, databases, backups, logs, plans and private Git history are excluded. Publication uses an exact file/hash allowlist and rejects unreviewed additions.

## Validation limits

Static checks and unit tests validate example code and syntax. They do not establish Nextcloud compatibility, live network security, backup restorability, WAN performance or production readiness. Human review remains necessary before publication.
